# Bruce — the USB-host audio subsystem (`usb_host_audio*.cc`, `usb_audio_receive.cc`, `audio_states.cc`) (session 18)

31 functions across 4 attributed source files, fully decompiled this session (all 4 files now 100% complete — see `bruce-decompile-status.md` §2/§3a). This is a coherent, previously-undocumented subsystem: `bruce` statically links a full **USB-host-mode USB Audio Class (UAC1/UAC2) driver**, layered under a higher-level policy module (`audio_states.cc`) that wires a USB audio device's mic/speaker endpoints into the "Synapse" AEC/AGC/NS voice-processing pipeline whose low-level FFT/IIR DSP primitives were already mapped in `bruce-itcm.md`.

## Why this is here at all

`bruce` is the BT-only firmware for the physical Stadia hand controller, which has no full-size USB-A host port — so a *USB-host* audio-class driver has no obvious on-controller consumer. `firmware-map.md` already flagged the sibling case: `bruce` and `gotham` (the Wi-Fi/WebRTC streaming firmware) share a base-platform SDK that includes "USB host stack with gamepad drivers (DualShock 3 / Switch Pro / Valve Steam Controller)" — i.e. code written for a different physical product (most plausibly a Chromecast-style streaming box that needs to host third-party USB peripherals) that got linked into `bruce` wholesale because both firmwares build from the same platform tree. This session's finding is the audio equivalent of that: a full UAC host driver plus a voice-processing policy layer, almost certainly dead code on the actual controller hardware but real, complete, shippable code in the image. Treat as **shared-platform code, not confirmed-active on this SKU** unless/until a caller into `audio_states__60075088` (the entry point below) is found from a code path known to run on the controller.

## Module map

### `usb_host_audio_topology.cc` (8/8 functions, 2876 bytes) — USB Audio Class descriptor topology parser

Parses the class-specific AudioControl (AC) interface descriptor block (Terminal/Unit descriptors per USB Audio Class 1.0/2.0 §4.3) into an in-memory `std::map`-shaped binary tree keyed by unit/terminal ID, then supports graph traversal over it (e.g. walking from an Output Terminal back through Mixer/Selector/Feature/Processing Units to the matching Input Terminal).

| Function | Size | Role |
|---|---:|---|
| `usb_host_audio_topology__60063cf4` | 212B | Decodes one raw AC-interface descriptor header into an internal node struct: a switch on descriptor subtype (`bDescriptorSubtype`, values 1–0x12) computes each subtype's expected minimum `bLength` (12 for Input Terminal/Mixer-shaped types, 0x11 for a 17-byte type, 9/6/10/8/7 for others, variable-length for Selector/Feature/Extension-Unit-shaped types that carry a trailing pin/channel-count byte) — i.e. a hand-written validator/sizeof table for every USB Audio Class terminal/unit descriptor subtype, confirming `iVar3`/`bDescriptorSubtype` values line up with the spec's `INPUT_TERMINAL`/`OUTPUT_TERMINAL`/`MIXER_UNIT`/`SELECTOR_UNIT`/`FEATURE_UNIT`/... enum. |
| `usb_host_audio_topology__60063e24` | 596B | **Topology builder.** Walks the raw AC-interface descriptor byte stream looking for `'$'`-tagged (0x24, `CS_INTERFACE`) chunks matching a unit-type filter, constructs a 0x34-byte tree node per match (via the 212B decoder above), and inserts it into the binary-tree topology map with a textbook Ghidra-recovered `std::map` red-black insert (`thunk_FUN_60101ccc`/`thunk_EXT_FUN_0000b52a` rotate/rebalance helpers). This is where the map consumed by every other function in this file gets built. |
| `usb_host_audio_topology__6006408c` / `600641a8` / `60064438` / `60064110` | 120B/622B/156B/142B | Map lookup, ID-chain parsing, recursive graph DFS (cycle-detected via a per-node "visited" byte), and a two-bucket node-list builder (tags nodes 0x100 vs 0x200 by a predicate) respectively — the traversal primitives used by the state machine below to resolve "which Feature Unit controls this Terminal" and "what's the active Clock Source". |
| `usb_host_audio_topology__60063c08` | 72B | Descriptor-length sanity `CHECK`. |
| `usb_host_audio_topology__600644dc` | 956B | **The big one — format/route resolver.** Given target sample-rate/channel/format criteria, walks a Terminal's connected AudioStreaming interface's alternate settings to find one whose Type-I/Type-II format descriptor matches, returning the winning altsetting index plus a sample-rate-range struct. Branches on `*(param_1+0x79)` (the AC interface's protocol byte) with two completely different code paths: `0x00` and `' '` (**0x20**) — these are exactly the real USB Audio Class `bInterfaceProtocol` values `IP_VERSION_01_00` (UAC1) and `IP_VERSION_02_00` (UAC2), confirming this driver supports both AC spec generations with genuinely different (fixed-endpoint-rate vs Clock-Source-object) format-negotiation logic. |

### `usb_host_audio.cc` (9/9 functions, 2346 bytes) — the UAC host driver's state machine

`usb_host_audio__6006318c` (1176 bytes) is a 17-state (`switch` cases 0–0x10) driver state machine, each transition posted via `usb_host_worker__600d56ae(obj, next_state)` (an already-attributed but not-yet-decompiled sibling file — the generic USB-host per-device worker/event-queue, out of scope this session). Inferred per-state roles (medium confidence — inferred from call targets + literal log strings, not cross-checked against a spec doc):

| State | Role |
|---:|---|
| 0 | Idle/no-op guard; cancels a stale pending I/O if re-entered. |
| 1 | Enumerate the device's interfaces looking for a usable AudioStreaming alternate setting (endpoint-count threshold check). |
| 2 | Find + claim the AudioControl (AC) interface by class/subclass; on success frees any stale topology and calls the topology builder (`usb_host_audio_topology__60064110`). Logs `"Unable to find control interface #%d"` / `"Unable to set control interface"` on failure. |
| 3 | GET_CUR the active Clock Source ID (UAC2 path) — `"Failed to query clock source #%d"` on error. |
| 4 | Resolve the Feature Unit IDs for each logical path (mic/speaker/sidetone, stored at `+0x35`/`+0x99`/`+0xfd`) via `usb_host_audio_topology__600644dc`, then SET_CUR the sampling frequency. `"Unable to find streaming interface(s)"` / `"Error setting interface units"` on failure. |
| 5 | Endpoint bandwidth/rate configuration — logs `"USB <speaker\|mic> will <play\|record> at <rate>kHz, <bits>-bit, <ch>ch"`; UAC1 path SET_CURs a fixed sampling-frequency endpoint request, UAC2 path SET_CURs the Clock Source/Clock Selector object instead. |
| 6 | Protocol-version gate: `0x00`(UAC1)/`0x20`(UAC2) proceed, anything else is an error. |
| 7, 8 | Feature-Unit GET/SET_CUR requests (mute / a second control) against the resolved Feature Unit ID at `+0x108`. |
| 9–12 | Select the active logical path (Speaker=0x82/Mic=0x83/Sidetone=0x84/Default=0x81, per `usb_host_audio__60062b1c`'s own switch) for the next Feature-Unit request. |
| 13 | Query + log the volume-control range (min/max/res/cur) for the active path's Feature Unit — via `usb_host_audio__60062aa8`/`60062a10`/`60062a74`, which log `"Mute change supported: %s"` / `"Volume change supported: %s"` / `"Min: %d Max: %d Res: %d Cur: %d"`. |
| 14 | Kick off isochronous IN (mic) and OUT (speaker) transfers for both directions via `usb_host_audio__60062f9c`. |
| 15, 16 | Terminal error states — `"Entering ERROR state"` / `"Entering invalid state"`. |

`usb_host_audio__60062f9c` (450B) is the isochronous transfer-completion handler shared by both directions: on each completed USB frame it advances a ring-buffer write cursor, detects overflow (notifies a waiting task via a semaphore-like primitive), and re-submits the next transfer (`usb_host_audio__60062ba4`/`60062c70`, mic-in vs speaker-out request builders, 178B/160B).

### `usb_audio_receive.cc` (8/8 functions, 1994 bytes) — the mic-in receive worker task

`usb_audio_receive__6007a62c` (772B, self-identifies via the log string `"Usb audio receiving thread is pr[oceeding]..."`) is a **FreeRTOS task loop**: waits on a task notification with an adaptive timeout (computed from a running buffer-fill estimate, `usb_audio_receive__60079f1c`'s underrun threshold logic), then on wake copies newly-arrived isochronous frames out of the double-buffered capture ring (`FUN_600dbbd0`) and, once enough data has accumulated, forwards a frame to the recording pipeline via a vtable call (`(**(code**)(*piVar6+8))()` — a generic "audio sink" interface, consistent with the intrusive-refcounted-object pattern documented in `bruce-itcm.md`). Uses the same `DataMemoryBarrier`/`ExclusiveAccess`/`hasExclusiveAccess` (LDREX/STREX) atomic-flag idiom seen in `bruce-itcm.md`'s atomic-refcount thunk, here guarding several single-byte "event pending" flags shared with the ISR/transfer-completion side.

`usb_audio_receive__6007a040`/`6007a504`/`6007a118` implement **sample-rate feedback / drift correction**: `6007a040` computes a 3-way rate-correction code (`+1`/`-1`/none) by comparing the buffer fill level against `0x180`/`0x900`/`0xcc0`-byte thresholds and pushes it out via `usb_device_audio__60061fc0` — this is the classic USB Audio Class 1.0 **feedback endpoint** (10.14 fixed-point rate value) mechanism for adjusting the source's isochronous rate to match the local clock. `6007a504` is the underrun/overrun-repair path (logs `"Not enough room in buffer to fill... ms audio gap"` / `"USB Audio discontinuity linear i[nterp]"`) that linearly interpolates across a detected gap. `6007a998` is the receiver object's lazy singleton constructor/refcount-acquire (first caller allocates + starts the task above; subsequent callers atomically bump a refcount via the same LDREX/STREX pattern).

### `audio_states.cc` (6/6 functions, 2392 bytes) — voice-path policy / AEC-backend selection

The policy layer that decides *how* to process mic/speaker audio and wires the USB-host-audio objects above into it.

- **`audio_states__60075088`** (1892B, by far the largest of the four files) — the entry point: creates a USB audio source (`usb_audio_receive__6007a998`) and sink (`usb_audio_send__6007ad34`, sibling file not decompiled this session), then reads a cluster of config keys via the generic typed KV store (`keys__60066370`, key IDs `0xf`–`0x13`, confirmed-attributed in `key_value_store.cc`/`keys.cc`) to pick an **echo-cancellation backend**: forced-off, `"Synapse"` (a named internal AEC/AGC/NS library — distinct from the literal-confirmed WebRTC/Ooura-FFT DSP chain in `bruce-itcm.md`, though it plausibly sits on top of the same primitives), with named AEC/NS/AGC sub-modes (`"SettingsDefault"` and others) and a processing sample rate (16 kHz default vs 48 kHz, delegated to `audio_states__60074c2c`). Constructs a `synapse_audio_processor` object (`synapse_audio_processor.cc`, sibling file, not decompiled this session) wired to the source/sink pair, then starts the capture (`recording_pipeline__6007ed74`/`6007edf4`) and playback (`audio_tasks__60079d28`) pipelines. On any failure it logs `"Audio setup failed to set the pl[ayback path]"` / `"Failed to setup audio paths and a[ctions]"` and unwinds. Confirms the literal chain `"Setting up usb audio source"` → `"Using 'Synapse' AEC"` / `"No AEC setting forced. Using... Synapse"` → `"Unknown echo cancellation type: %s"` seen directly in the decompiled strings.
- **`audio_states__60074c2c`** (124B) — reads config key `0x13`/type `7`, matches literal strings `"default"`/`"16000"`/`"48000"`, returns the internal-processing-rate flag (defaults to 16 kHz, logs which rate was chosen and why).
- **`audio_states__60074e6c`/`60074d54`/`60074dfc`/`60074f70`** (80B/44B/56B/196B) — small ctor/on-enter/on-exit-shaped handlers (one constructs a refcounted wrapper object with an explicit vtable pointer, `PTR_PTR_60075034`; two others are trivial "if channel present, do X else log" pairs). Shape strongly suggests these are concrete state-callback instantiations of the generic hierarchical-state-machine framework documented in `bruce-state-machine.md` (on-enter/on-exit dispatch), though no direct caller into the base-class dispatcher was traced this session — flagged as a loose end below rather than asserted.
